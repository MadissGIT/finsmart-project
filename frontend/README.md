# ФинСмарт Frontend

React 18, TypeScript, Vite и Tailwind. Мобильные экраны регистрации, финансовый
обзор и операции связаны с FastAPI. Данные загружаются из PostgreSQL через API;
в приложении нет заранее созданных операций или копилок.

## Запуск

Нужны Node.js 24+ и npm, для backend — работающий Docker.
Из корня репозитория запустите API и PostgreSQL:

```bash
docker compose up --build --wait --wait-timeout 180
```

Во втором терминале:

```bash
cd frontend
npm ci
npm run dev
```

Откройте [Welcome](http://127.0.0.1:5173/welcome) или
[Обзор](http://127.0.0.1:5173/). Создайте аккаунт либо войдите в существующий.
Прежний демонстрационный вход не создавал пользователя на сервере.
Новый аккаунт открывается с нулевыми показателями и без операций.

Если 5173 занят уже запущенным frontend, используйте существующую страницу
или остановите свой сервер через Ctrl+C. Также можно запустить
`npm run dev -- --port 5174` и открыть указанный адрес. В проекте включён strictPort.

## Дашборд третьей недели

- Доходы, расходы и баланс приходят из `GET /api/v1/analytics/budget`.
- Баланс — разница доходов и расходов за выбранный период, включая отрицательные значения.
  Это не запрос банковского остатка на карте.
- Диаграмма Recharts поддерживает подсказки, выбор сектора и выбор категории
  кнопками с клавиатуры. При выборе показываются сумма и доля категории;
  выбор можно сбросить. Цвет категории сохраняется при смене периода.
- Полосы бюджета показывают выполнение ориентиров 50/30/20. Реальные суммы,
  доли, целевые суммы и отклонения берутся с сервера. Полоса ограничена 100%,
  а фактическое превышение остаётся видимым в цифрах.
- Индекс «Соблюдение бюджета» использует `budget_score`, а не общий Health Score.
  Если доходов нет, показано объяснение серверной базы расчёта от расходов.
- Текущий и прошлый месяц, последние 7 и 30 дней, свой диапазон передаются
  серверу как `from_date` и `to_date`. Обе даты включены, максимум 367 дней.
- Выбранный период записан в URL. Обновление страницы и история браузера
  восстанавливают его; ссылка из бюджета в аналитику сохраняет фильтр.
- При смене периода прежний запрос отменяется, а его поздний ответ не заменяет
  актуальный результат. Загрузка, ошибка, повтор, пустой аккаунт и гость
  отображаются отдельно. При ошибке суммы прошлого периода не показываются.

### Динамика расходов

В «Аналитике» столбчатый график берёт даты из общего фильтра. Переключатель
«По дням» / «По неделям» отправляет выбранную группировку в
`GET /analytics/expenses/trend`. В первую и последнюю неполную неделю
включены только даты выбранного периода. Точные суммы доступны в подсказках
и в таблице под графиком.

### Финансовый диагноз

Для вошедшего пользователя дашборд запрашивает `GET /analytics/dashboard`.
В блоке показаны серверный рейтинг, его составляющие, предупреждения и
подходящие акции из каталога. Без операций выводится пустое состояние.
Если выбрано больше 31 дня, диагноз строится за заключительный 31 день
выбранного диапазона, а бюджет и суммы сохраняют полный диапазон.

## Вход и регистрация

`/register` проверяет email, пароль 10–128 символов, его подтверждение и
ознакомление с информацией о сервисе. На `/register/profile` нужно имя;
после отправки вызывается `POST /auth/register`.
Пароль первого шага существует только в памяти до отправки и не сохраняется
в storage. При обновлении страницы до создания аккаунта его нужно ввести снова.

`/auth` отправляет email и пароль в `POST /auth/login`, затем получает профиль
через `GET /users/me`. При 401 access автоматически обновляется через
`POST /auth/refresh`; параллельные запросы используют одно обновление.
Недействительная refresh-сессия завершает вход. Выход и смена аккаунта
не позволяют завершившимся старым запросам восстановить сессию.

Access и refresh хранятся в sessionStorage текущей вкладки, поскольку API
возвращает токены JSON. Пароли в browser storage не сохраняются.
Цель использования и диапазон дохода — отдельные настройки анкеты для вкладки;
они не создают финансовые операции. Дата рождения необязательна и сохраняется
в профиле на сервере. Вход через Yandex пока недоступен. Вход через Google
не подключён.

## Добавление личных данных

На `/setup` выберите CSV/XLSX кнопкой или перетащите файл в область загрузки.
Выберите банк и нажмите «Импортировать выписку».
Файл до 5 МБ отправляется в `POST /transactions/import-statement` с Bearer-токеном.
Выбор файла сам по себе его не отправляет. После импорта показаны числа
добавленных операций, повторов и пропущенных строк. В обзоре выберите период выписки.
Поддерживаемые форматы и особенности банков описаны в `backend/docs/week-2.md`.

## Операции

На `/transactions` доступен список с группировкой по дням, поиском по организации
и описанию, фильтрами по типу, одной категории и датам. Фильтры и страница
сохраняются в URL. Сервер возвращает по 20 операций на страницу; суммы в заголовках
дней относятся только к показанным строкам.

Кнопка «+» на дашборде или в списке открывает добавление дохода/расхода.
Сумма, категория, организация и дата обязательны, комментарий необязателен.
Карточка операции поддерживает редактирование, очистку комментария, смену
категории и удаление с подтверждением. Успех показывается после ответа API.
Запомненная категория применяется при будущих импортах в аккаунте пользователя.

Новый аккаунт не содержит операций.
[Устройство и проверка операций](docs/transactions.md).

## Скидки

На `/discounts` каталог загружается с сервера. Фильтр категории передаётся API,
поиск по магазину, названию и категории применяется к загруженным акциям.
Подборка для вошедшего пользователя строится сервером по тратам за 30 дней.
Из аналитики можно открыть предложения выбранной на диаграмме категории.

Карточка показывает выгоду, срок, условия и промокод, если он есть.
Предложения без подтверждения от партнёров отмечены «Демо».
Избранное хранится в браузере отдельно для каждого аккаунта и гостя.

## Ещё

В разделе «Ещё» доступны база знаний, вопросы и ответы, сведения о приложении
и проверка подключения. База знаний загружает список и текст статей из API.
Темы фильтруются на сервере, поиск работает по загруженным статьям.
Избранные статьи сохраняются в браузере.

## Копилки

На `/goals` можно создать копилку, указав название, сумму, срок и значок.
Список показывает прогресс и статус, а карточка цели — месячный и недельный план,
редактирование, виртуальное пополнение и историю взносов. План и история
загружаются из API. Взносы учитываются в копилке без банковского перевода.
На дашборде выводится ближайшая активная цель.

## API и настройки

Общий axios-клиент использует `/api/v1`, таймаут 10 секунд и Bearer-заголовок.
Vite направляет `/api` на `http://127.0.0.1:8000` с сохранением пути.
Для другого адреса скопируйте `.env.example` в `.env.local`, измените
`API_PROXY_TARGET` и перезапустите Vite.

Пресеты периода используют часовой пояс финансов Europe/Moscow, как backend
по умолчанию. При изменении `FINSMART_FINANCIAL_TIMEZONE` на сервере задайте
такой же `VITE_FINANCIAL_TIMEZONE` для frontend.

Readiness и справочник категорий можно проверить на странице `/more`.
Ответы профиля, токенов, операций и аналитики проверяются во время исполнения.
[Действующие контракты](docs/api-contracts.md), [результат недели 3](docs/week-3.md),
[источник дизайна](docs/design.md).

## Проверки

```bash
npm run lint
npm run test
npm run build
npx playwright install chromium
npm run test:e2e
```

Обычные браузерные проверки используют тестовый HTTP upstream и перехваты
ответов, чтобы воспроизводить ошибки, задержки и обновление сессии.
Фикстуры находятся в `e2e/` и не подключаются к приложению.
Для запуска одновременно с dev-сервером можно задать `E2E_PORT=5175`.

Отдельный комплект проверяет настоящий FastAPI и PostgreSQL без перехвата API.
Чтобы не добавлять тестовые записи в обычную БД, запустите отдельный project
из корня репозитория:

```bash
FINSMART_API_PORT=18001 docker compose -p finsmart-frontend-e2e up --build --wait --wait-timeout 180 api
cd frontend
API_PROXY_TARGET=http://127.0.0.1:18001 E2E_PORT=5176 npm run test:integration
```

После проверки из корня удалите только тестовый project:

```bash
FINSMART_API_PORT=18001 docker compose -p finsmart-frontend-e2e down --volumes
```

Интеграционные тесты создают отдельные учебные аккаунты и операции. Они проверяют
регистрацию, вход, импорт настоящего CSV, агрегацию периодов, отрицательный
баланс, пустой период, график, бюджет и ротацию refresh. Проверки операций
проходят создание, редактирование, очистку комментария, удаление, серверные фильтры,
переход по страницам и применение запомненной категории при импорте. Снимки результата
сохраняются в `test-results/`. В GitHub Actions для этого выделена отдельная
задача с FastAPI/PostgreSQL и артефактом frontend-backend-browser-evidence.

## Сборка для размещения

`npm run build` создаёт `dist/`. На сервере размещения маршруты SPA нужно
направить в `index.html`, а `/api/*` — в backend. Dev-прокси Vite не входит в dist.
