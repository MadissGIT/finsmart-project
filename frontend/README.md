# ФинСмарт Frontend

Каркас SPA для первой недели: React 18, TypeScript, Vite и Tailwind CSS.
Общий Layout, маршруты и типы API подготовлены для дальнейшей работы над MVP.

## Запуск

Нужны Git, Node.js 24 и npm. Версия Node указана в `.nvmrc`.

```bash
git clone --branch frontend-week-1 https://github.com/MadissGIT/finsmart-project.git
cd finsmart-project/frontend
npm ci
npm run dev
```

Открыть [http://127.0.0.1:5173](http://127.0.0.1:5173).
Для просмотра страниц backend не требуется.

## Что готово

| Маршрут | Состояние первой недели |
| --- | --- |
| `/` | Пример финансовой сводки и виджета диагноза, проверка соединения с API |
| `/transactions` | Заглушка для операций и импорта выписок |
| `/analytics` | Пример кольцевого графика Recharts и распределения 50/30/20 |
| `/goals` | Заглушка для копилок |
| `/auth` | Заглушка профиля и авторизации |

Неизвестный адрес открывает страницу 404. На экранах от 768px виден Sidebar,
на смартфонах — нижний MobileNav. Header содержит место для баланса и профиля.
Пока аккаунт не подключён, баланс показан как `— ₽`, ссылка профиля ведёт на `/auth`.

Цифры на страницах обзора и аналитики взяты из раздела 4.3 проектной документации
и помечены как демонстрационные. Это не результат запроса к backend.
Авторизация, импорт, CRUD операций и целей ещё не реализованы.
Формы авторизации и загрузка выписки отнесены в документе к зоне Frontend 2.

## Проверка связи с backend

В `backend-week-1` уже есть `GET /api/v1/health/ready`. Для проверки запустить
backend из этой ветки в отдельной папке по его README. Например, во втором терминале:

```bash
git clone --branch backend-week-1 https://github.com/MadissGIT/finsmart-project.git finsmart-backend
cd finsmart-backend
docker compose up --build --wait --wait-timeout 180
```

Затем на странице обзора нажать «Проверить подключение».

Путь запроса:

```text
Браузер → http://127.0.0.1:5173/api/v1/health/ready
Vite proxy → http://127.0.0.1:8000/api/v1/health/ready
```

Общий axios-клиент находится в `src/shared/api/client.ts`: `baseURL: '/api/v1'`,
таймаут 10 секунд. Прокси перенаправляет `/api` без удаления префикса.
Для работы через этот прокси дополнительная настройка CORS не нужна.

Если backend слушает другой адрес, скопировать `.env.example` в `.env.local`
и изменить `API_PROXY_TARGET`. После изменения перезапустить Vite.
Эта переменная используется конфигурацией dev-сервера и не попадает в клиентский JS.

Успех означает ответ `{"status":"ok"}`. `503` означает, что backend не готов,
например, недоступна БД или не применены миграции. Ошибка соединения обычно
означает, что backend не запущен или адрес/порт не совпадают.

`getDashboard()` уже описывает будущий запрос аналитики, но пока не вызывается:
в backend первой недели этого endpoint нет. JWT и хранение токенов будут
подключаться вместе с реальной авторизацией.

## Структура

```text
src/
  app/        # сборка приложения, роутинг, глобальные стили
  pages/      # страницы маршрутов
  widgets/    # Layout, сводка, график, бюджет, диагноз
  features/   # проверка соединения с сервисом
  entities/   # типы предметных областей, пример ответа аналитики
  shared/     # axios-клиент, форматирование, общие UI-элементы
```

Используется упрощённый FSD с группировкой по предметным областям.
Импорты идут сверху вниз: `app → pages → widgets → features → entities → shared`.
Неиспользуемые слои и пустые заготовки под будущие функции не создаются.
Алиас `@/` указывает на `src/` и одинаково настроен в Vite и TypeScript.

Подробности соответствия контрактам: [docs/api-contracts.md](docs/api-contracts.md).

## Проверки

Выполнять из папки `frontend`:

```bash
npm run lint
npm run test
npm run build
npx playwright install chromium
npm run test:e2e
```

Браузерные тесты сами запускают Vite на 5173 и тестовый HTTP upstream на 18080;
эти порты должны быть свободны. Проверяются прямые URL и обновление страниц,
навигация, история браузера, мобильная вёрстка, отображение графика, запрос
через настоящий Vite proxy, ошибки API и повтор запроса.

Upstream в e2e — тестовый сервер, а не FastAPI. Эти тесты проверяют связку
браузер → axios → Vite proxy → HTTP, но не соединение FastAPI с PostgreSQL.
Проверка реального backend выполняется отдельно по инструкции выше.

GitHub Actions запускает линтер, модульные тесты, сборку и браузерные тесты
при пуше в ветку фронтенда и в pull request.

## Сборка для размещения

`npm run build` создаёт `dist/`. `npm run preview` позволяет посмотреть
готовую статику локально. В production нужно отдельно настроить сервер:
неизвестные пути SPA направлять в `index.html`, а `/api/*` — на backend
с сохранением пути. Dev-прокси Vite в `dist/` не переносится.

Справка по настройкам: [Vite proxy](https://vite.dev/config/server-options#server-proxy),
[Tailwind с Vite](https://tailwindcss.com/docs/installation/using-vite),
[Recharts](https://recharts.github.io/en-US/guide/).
