# Операции: интерфейс и интеграция

Экран `/transactions` заменяет прежнюю заглушку. Реализованы список, карточка,
добавление дохода/расхода, редактирование, удаление, фильтры и исправление категории.
Используется существующий FastAPI из main; код backend в этой задаче не менялся.

## Дизайн

Источник — [мобильные транзакции в Figma](https://www.figma.com/design/x8MvvpTA5kYbVzB8GTvnTf/ФинСмарт?node-id=477-2748).
Для этого раздела доступны слои и оригинальные ресурсы макета:

SVG и иллюстрация хранятся в `public/figma/transactions/`, временные адреса Figma
не используются приложением. Геометрия SVG сохранена. Заголовки используют Manrope,
основной текст — Inter. На смартфоне формы открываются снизу, фильтры сбоку;
на широком экране форма располагается по центру. Мобильный макет рассчитан
в том числе на ширину 320 px. Поля ввода на сенсорных устройствах имеют шрифт 16 px.

Имена категорий поступают из справочника API. Логотипы организаций не зашиты
в строки: сервер их не возвращает, поэтому используются значки категорий.
Поиск, единственный выбранный фильтр категории и постраничная загрузка
соответствуют возможностям API. Фильтр дат и подтверждение удаления добавлены
для полного рабочего сценария.

## Состояние

Фильтры `q`, `operation_type`, `category_id`, `from_date`, `to_date`, `page`
и открытая операция `transaction` находятся в URL. Поиск задержан на 300 мс.
Предыдущий запрос отменяется, а его запоздалый ответ не заменяет новый список.
Повторная отправка формы и её закрытие блокируются на время записи. При ошибке
форма сохраняет введённые значения. Выход и смена аккаунта убирают прежние данные
и не допускают применения завершившихся старых запросов к новой сессии.

При обычном обновлении access-токена уже проверенный профиль сохраняется
в пределах той же сессии. Это позволяет не закрывать открытую форму во время
refresh. Ошибка загрузки профиля и недействительная сессия обрабатываются отдельно.

## Проверка

Команды приведены в `frontend/README.md`. Модульные проверки охватывают контракт
операции, сериализацию фильтров, денежные ограничения и часовой пояс.
Браузерные проверки используют desktop и mobile, включая ширину 320 px,
ошибки и задержки API. Отдельный комплект работает с настоящими FastAPI/PostgreSQL
в изолированном Docker project и проверяет сохранение после reload,
обновление дашборда, refresh во время отправки формы, запрет доступа другого
аккаунта и применение запомненной категории к следующему импорту.

Учебные аккаунты и операции существуют только в тестах. Приложение не создаёт
демоданные для пользователя. Скриншоты тестов служат свидетельством проверки,
а не источником данных интерфейса.
