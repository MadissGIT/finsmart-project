# Неделя 3 Аналитика и копилки

## Аналитика

Запросы требуют Bearer-токен. `GET /api/v1/analytics/dashboard` возвращает
поля бюджета и блок `diagnostics`: оценку от 0 до 100, четыре субиндекса,
статус, цвет, профиль и список сработавших правил. Без дат берутся последние
30 календарных дней, включая сегодня. Для явного периода передайте
`from_date` и `to_date` (YYYY-MM-DD, обе даты включительно, 1–31 день).
Границы считаются в `FINSMART_FINANCIAL_TIMEZONE`. Для сравнения расходов и
поиска подписок анализируется до 90 дней истории. `GET /analytics/budget`
сохраняет контракт второй недели.

Health Score использует веса 35/25/25/15 для баланса, соблюдения бюджета,
взносов в цели и регулярности учёта. Если дохода нет, индексы баланса и
бюджета равны нулю. Если нет плана по целям, индекс целей равен 50.
Для целей план строится от остатка на начало периода (или дату создания),
с учётом дедлайна и доли дней расчётного месяца; для FD-10 каждый план
проверяется по взносам, сделанным до дедлайна включительно.
Исторические расчёты используют текущие параметры целей.
Регулярность считается по времени записи операций: четыре последовательных
интервала по семь дней до конца периода. Неделя активна, если есть хотя бы
одна сохранённая импортированная операция или три ручных записи. Импорт
без новых строк и удалённые операции в эту метрику не входят.

| Код | Условие |
| --- | --- |
| FD-01 | Wants >45% дохода, сбережения <5% |
| FD-02 | От четырёх регулярных пар «контрагент + сумма» в подписках, >1500 ₽; для каждой пары есть повтор с интервалом 28–31 день |
| FD-03 | Более 20 покупок в кафе по 150–400 ₽, вместе >4500 ₽ |
| FD-04 | Такси и каршеринг >15% расходов, рост >20% к предшествующему периоду той же длины; при нулевой прошлой сумме рост не вычисляется |
| FD-05 | Расходы выше дохода или остаток <3% от ненулевого дохода |
| FD-06 | Супермаркеты >40% дохода |
| FD-07 | От 35% Wants за первые 72 часа после поступления в категории доходов |
| FD-08 | Сбережения >30%, нет незавершённых целей и подтверждён беспроцентный остаток ≥60 дней |
| FD-09 | Более 8 покупок на маркетплейсах, сумма >12000 ₽, средний чек <1500 ₽ |
| FD-10 | Доли 50/30/20 в пределах пяти процентных пунктов, нет дефицита, есть план по целям и он выполняется |

Алерт содержит код (`type`), категорию, заголовок, сообщение и рекомендацию.
Для FD-03/FD-06 API возвращает до пяти действующих предложений из таблицы
скидок, если они есть. FD-10 возвращает бейдж `financial_zen`.

FD-08 нельзя подтвердить по транзакциям. Для него можно вызвать
`POST /api/v1/analytics/dashboard` с телом
`{"idle_cash":{"since":"2026-09-01","amount":100000}}` и при необходимости
добавить `from_date` и `to_date`. Данные пользователь сообщает сам; они не
сохраняются. Обычный GET отмечает FD-08 в `diagnostics.unavailable`.

## Копилки

| Метод | Путь от /api/v1 | Назначение |
| --- | --- | --- |
| GET | /goals | Список своих копилок |
| POST | /goals | Создать (201): title, target_amount, deadline, необязательный icon |
| GET | /goals/{id} | Копилка и её текущий план |
| PATCH | /goals/{id} | Частично обновить поля создания |
| POST | /goals/{id}/deposit | Внести amount с source: free_money или discount |
| DELETE | /goals/{id} | Удалить копилку с историей взносов (204) |

Чужие и отсутствующие копилки дают 404. Новый дедлайн не может быть в прошлом.
Взнос положительный, до двух знаков после запятой, не выше остатка до цели.
Взносы сериализуются блокировкой строки копилки. Пополнение виртуальное и не
создаёт банковской транзакции или реального перевода.

Месяцы до дедлайна рассчитываются как дни / 30,4. Месячный взнос равен остатку
до цели, делённому на максимум из единицы и числа оставшихся месяцев. Недельный
равен месячному / 4,33. План вычисляется заново по текущему остатку и дате,
дедлайн при этом сохраняется. Флаг `exceeds_half_income` включается, если
требуемый взнос выше половины учтённого дохода текущего месяца. Поле
`warning` объясняет причину и предлагает продлить срок или уменьшить цель.
Для взноса из скидки `acceleration_days` — округлённое отношение суммы
к дневному темпу до взноса (месячный план / 30,4).

Точность категоризации на реальных выписках здесь не измерялась. Числа из
чернового отчёта ТЗ не заменяют прогон по размеченному набору.
